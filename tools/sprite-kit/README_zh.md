# 精灵工具包

小镇地图上的人物、建筑和道具不是页面在运行时画的，而是由这个工具包在构建时渲染一次：一个我们自己写的小型 WebGL2 光线步进器（有向距离场、卡通着色和墨线，不用任何库，也没有模型文件），把每个精灵的每一帧烘焙进两张图集和一份清单。游戏页面只负责把这些帧画出来。

```
node tools/sprite-kit/bake.mjs [--jobs 4] [--only char.li_da,place.bridge] [--scales 1,2] [--px 56] [--out out] [--kmax N]
```

它需要 Node 22，以及 `web/` 里的 Playwright 和它的 Chromium。脚本在 `../../web` 里找 Playwright，环境变量 `KIT_PLAYWRIGHT_FROM` 可以指向另一个 `web/` 目录。软件 WebGL 就够用，显卡只会让烘焙更快。`--jobs` 是同时烘焙的浏览器个数，`--scales` 是要生成的图集（`1,2`），`--px` 是 1 倍图下每个世界单位的像素数，`--only` 只烘焙这些 id 或 id 前缀的精灵，`--kmax N` 只烘焙每个动画的前 N 帧。带其中任何一个的烘焙写出的清单是不完整的，所以只用来看效果，不用来发布。最重的帧最先烘焙，每帧 2 倍图渲染时要占几 GB 内存，所以每多一个任务就要多这么多内存。

## 它写出什么

`out/` 里有 `atlas-1x.webp`、2 倍图集（`atlas-2x.webp`；高过 4096 像素时是 `atlas-2x-1.webp` 和 `atlas-2x-2.webp`）（都是无损的）、`manifest.json`，以及两张给人看的图：标出每个精灵的锚点和占地的 `contact-sheet.png`，还有 `walk4.gif`。这次运行的耗时写在 `bake.mjs` 旁边的 `bake-report.json` 里。Git 忽略 `out/` 和这份报告。

清单（`schema: lantern-eve/sprite-kit@1`）就是它和页面之间的全部约定。里面有相机和单位（一个网格在屏幕上宽 32 像素、深 25.22 像素，高度每个世界单位上移 34.48 像素）、图集文件，以及每个精灵的帧大小、锚点、每一帧在每张图集里的位置，还有摆放这个精灵所需的信息：

- 人物有动画 `idle`、`walk` 和 `talk`，带东西的人物还有 `carry`。每个动画有 `down`、`up`、`left`、`right` 四个朝向，它们是各自单独渲染的。`walk` 带有一步的跨度（像素）。锚点是两脚之间的地面点。工具包为镇上的二十位人物和总管各画了一个自己的小人，另有三个镇上的路人（男、女、孩子）。谁用哪一个，由 `web/src/page/map/sprites.ts` 说明。
- 建筑有以格为单位的占地，锚点在占地西南角的地面上。房屋带有两盏门灯的挂点，有窗的建筑会指明它点亮的窗的精灵（`lights`，见下文），桥带有行人走在桥面上被抬高的高度。
- 道具和特效带有占地或混合模式，灯笼说明它的光晕放在哪里。树、青苔石堆和杂物堆是占地一格的道具。

帧大小、锚点和偏移量都以 1 倍图的像素计。2 倍图是同样的帧、两倍的大小。页面两种图集都按 1 倍图的逻辑大小来画。

## 夜里的窗

有窗的建筑还有第二个精灵 `fx.windows.<名字>`，它不是这座建筑的第二份副本。它只是点亮的窗格，加上挂在建筑上的灯笼纸，用同一个模型在光线步进器的一个模式（`uMode 1`）里渲染一次：窗格是平的暖色，其余一切都是透明的，但仍然挡住它后面的东西。窗格前面的窗棂仍是暗的，所以光是从窗棂的缝里透出来的。页面在夜里把这个精灵叠加到建筑上方的画面里，锚点和建筑的锚点一致，白天什么也不画。建筑的清单项用 `lights` 指明它，它自己的清单项里用 `spots` 记着窗的位置：`[x, y, w, h]`，以 1 倍图像素、从它的锚点算起（y 向下），页面在每扇窗上放一圈柔和的光晕。同一座建筑的各个实例共用这一个精灵：两座李家宅和两座周家宅各共用一个，摊位和桥没有。

## 页面角落里的物件

有四个精灵不是给地图用的。它们是给页面角落用的，总管在那里放着办事的东西：`prop.elder_seal`（族长印，一方石印，印面刻着「族」字，印钮上系着一根红绳）、`prop.notebook`（见闻簿，平放的线装书，签条上写着「见闻簿」，书脊在右边，和旧书一样），以及 `prop.incense_unlit` 和 `prop.incense_lit`（一只青铜香炉插着一炷香，和同一只香炉点着的样子：香头发红，一缕烟升起来）。它们和人物、道具走同一条管线烘焙，用同一台相机和同一盏灯，1 倍图下高 57 到 71 像素。每一件都立在一个点上，没有占地。两只香炉是同一个模型，所以页面把它们互相替换时，把锚点对齐，什么都不会动：点着的那只在锚点上方多出一缕烟，锚点下面留的空间一样。

页面像画清单里的任何一个精灵那样画它们：`frames` 给出图集里的 `[page, x, y]`，`frame` 是 1 倍图的像素大小，`anchor` 是帧里的地面点。

这些物件有自己的着色器程序。`src/shaders/objects.glsl` 里是它们的三个模型、材质和挑选哪个模型的代码，`engine.js` 把它编译成名为 `objects` 的程序：同一个光线步进器和人物代码，只是用这些模型代替那些场景。烘焙其他每个精灵的程序里没有这些模型，它的贴字画布里也没有，所以给工具包添加物件，永远不会改动图集里已有的精灵。印上的字和签条上的字是马善政的轮廓（`src/page/glyphs.js`，由 `tools/fonts/glyph_paths.py` 生成），由 `places.js` 里的 `makeObjectsDecal` 画在它们自己的贴字画布上。

## 比较两次烘焙

```
node tools/sprite-kit/compare.mjs web/public/sprites tools/sprite-kit/out [--partial]
```

它在 Chromium 里解码两个目录的图集，逐精灵、逐帧比较像素的每一个字节，也比较每个精灵的清单条目（不含各帧的位置，因为加了精灵之后帧在图集里会移位，它们的像素不会变）。只有新清单里才有的精灵会被列出来，不算错误。`--partial` 还允许新清单缺少一些精灵，用于带 `--only` 的烘焙。全部比较的内容都一致时，退出码是 0。

## 美术放在哪里

`web/public/sprites/` 里放页面要加载的文件：图集（`atlas-1x.webp`，以及 2 倍图装不进一页 4096 像素时的 `atlas-2x-1.webp` 和 `atlas-2x-2.webp`）和 `manifest.json`。烘焙之后，先把那里的旧图集删掉，再把新文件从 `out/` 复制过去。

```
rm web/public/sprites/atlas-*.webp
cp tools/sprite-kit/out/atlas-*.webp tools/sprite-kit/out/manifest.json web/public/sprites/
```

页面读取清单，不从固定位置取任何一帧。清单里新增的精灵，只要 `web/src/page/map/sprites.ts` 说明了它画的是谁或什么，就不需要改代码。

## 烘焙是确定的

相同的源文件和相同的选项，得到逐字节相同的文件。浏览器完成的先后顺序不影响结果，因为帧在打包前会排好序，Chromium 加进图片的颜色配置也被剪掉了，所以任何加载器看到的颜色都一样。每次运行都会不同的耗时不写进 `out/`。因此 `web/public/sprites/` 下这四个文件（图集和 `manifest.json`）有变化，就说明源文件或选项变了。

## 源文件

- `bake.mjs` 启动浏览器，把帧分给它们，打包图集并写出文件。
- `src/shaders/` 是 GLSL：`march.glsl` 是光线步进器，`figures.glsl` 是人物，`places.glsl` 是茶馆、两家的宅子、栈桥、石桥、竹竿堆、灯笼和垂柳，`town.glsl` 是其他的建筑（普通房屋共用一个主体，每座建筑再有一个函数写它自己的特点），`trees.glsl` 是树、石堆和杂物堆，`dispatch.glsl` 决定地点用哪个模型、地点材质的反照率（以及夜里的光），`common.glsl` 是它们共用的函数，`post.glsl` 是墨线和最后一遍处理。
- `src/shaders/objects.glsl` 是页面角落物件的程序，`compare.mjs` 比较两次烘焙。
- `src/page/` 在浏览器页面里运行。`config.js` 有单位、相机、光照和调色板，`engine.js` 是 WebGL2 引擎，`catalog.js` 有人物和他们的动画，`places.js` 有建筑和道具及其占地（取自 `content/maps/bridge_town.yaml`）以及据此生成的点亮的窗，`bake.js` 烘焙一帧，`compose.js` 裁剪并打包帧（并找出夜里的光的窗在哪里），`gif.js` 生成预览，`glyphs.js` 存着印上和签条上那几个字的轮廓。

# README pictures

The pictures in `docs/assets/` that the two READMEs show are made by the scripts in this folder. They need Node 22, ffmpeg and a headless Chromium (the "headless shell" build), and add no package to the project.

```
export CHROME_BIN=/path/to/chrome-headless-shell
```

Without `CHROME_BIN` the scripts use the headless shell that `npx playwright install chromium` puts in Playwright's browser folder: `PLAYWRIGHT_BROWSERS_PATH` if it is set, else `~/.cache/ms-playwright` (Linux only). The browser is started with `--incognito` and with its profile and temporary files in the directory given by `--tmp` (default: the system's temporary directory). Chinese text uses Noto Sans CJK SC, so that font has to be installed. ffmpeg is taken from `PATH`, or from the variable `FFMPEG`.

## Figures

`figures/` holds one HTML file per figure: `banner` and `architecture`. Each is a single rounded card. `figures.css` defines the colours as variables for the light and the dark theme, and every text exists twice, as `<span class="en">` and `<span class="zh">`, so one source gives four pictures. `connect.js` draws the arrows between the boxes. The title faces are the two fonts that the game page bundles in `web/public/fonts`.

```
node tools/readme_assets/build.mjs
```

writes `docs/assets/<figure>-<en|zh>-<light|dark>.png` at twice the pixel ratio, with a palette of 256 colours. `--only banner`, `--lang zh`, `--theme dark`, `--colors N` (0 keeps the true-colour PNG), `--out DIR` and `--tmp DIR` narrow or redirect it, and a PNG over 400 KiB is an error. To look at a figure in a browser, open `figures/banner.html?theme=dark&lang=zh`.

## Pictures of the page

`capture_page.mjs` drives the real game page: the test build of the web client, with the real core running in Pyodide behind it. It serves `web/dist-e2e` on 127.0.0.1 (a port the system picks), opens the page in the browser through the Chrome DevTools Protocol, and takes screenshots. The test build comes first:

```
(cd web && npm ci && npm run build:e2e)
node tools/readme_assets/capture_page.mjs
```

It makes four pictures, each in the light and the dark theme and in Chinese and English:

- `play-<lang>-<theme>.gif` is the first day of the game as a player meets it. The page is opened without a game in its address, so it shows its opening page and plays the game the opening page starts, with its own seed, held until Start. The film shows the opening page, the page of the first six people, and the clan elder's first card, which sends the manager to Granny Li by the underlined phrase on the red slip. The manager walks up to her and the talk opens: four buttons, her name and who she is beside them, a row of hearts, and the preview of the one request the slip names, the bamboo. She refuses, and the elder's second card says why and where to go next. What stands behind the hearts opens from the hearts, and the small things that can be given are listed. The rumour is followed back from Granny Li to the teahouse keeper and to Zhou's Clerk, with the question the slip names and the list of notes to ask the source of. The notebook then opens by itself at the pair of lines that the elder set side by side, and the film shows its book of the people first. A wrong answer says to think again, and the right one is that what the clerk saw does not support what the town says. After a cut to the afternoon it is the evening at the teahouse: the elder's last card, the small cards of the acts that open there, and the notebook, from which the judged pair is said in public. Each person there answers in their own words, and Granny Li takes her objection back. Li Da is then asked for the bamboo, the preview first, and promises. At nine in the evening the lamp-lit note that sums up the night holds the world until it is put away, and after a cut through the night it is the next morning: the Town Gazette is up, then the card that says the first day is done, and then the camera comes to the bridge, where the bamboo lies as a pile beside the ledger that says what was promised and what has come. A cut is a stretch of ticks that the script steps through with no picture. ffmpeg makes the GIF from a palette of all its frames.
- `notebook-<lang>-<theme>.png` is the notebook, a book bound with thread, at the moment the manager has judged that pair. The left page holds the notes: the line set against the claim, the three answers, what came of the answer, the hint, and the list of the pairs compared. The right page is the statement card, still empty. The book is shown as tall as the page makes it when no line of help (the tutorial, a hint) is up, and the picture is cut at the line of ink inside the hand-cut edge of its paper. What lies round the book (the note of the slip, the strip of the talk, the note of the person) is put away for the picture. No line of the book is. A page of the book is longer than the book is tall, and the phrase that turns it lies over its foot, so the script scrolls each page, the way a player does, to a place where neither the top edge of the page nor the phrase cuts an entry (a title, a paragraph, a row of a list, a button). The left page has to show what came of the answer, and the right page its third blank with all its accounts. Among the places that qualify, the script takes the one that shows the most of the hint, the title of the pairs compared and the pair judged, and then the highest. Where a rule of the page would show a few pixels over the rule of the phrase, the phrase is made as tall as it takes to cover it, so that nothing but the rule lies under it. After the picture the script reads the place of each page again and stops with an error if an entry is cut. With `--only notebook` the script stops there and does not play the rest of the day.
- `ending-<lang>-<theme>.png` is the rumour tree of an ending, from a game of one day that runs to its last night with nobody at the helm. The title above the tree sets the first version of the rumour against the last, and the tree holds only what was told in the game, so in a game in which the rumour does not travel as far as its title says, the title ends on a sentence that nobody in the tree holds. The script reads the title and the words under the names from the data of the page, and stops with an error for such a game.
- `festival-<lang>-<theme>.png` is one moment of the festival night, from a game whose last night is the full one. The core's test actions set the goals of that game at its first tick (the families called, the bamboo and the timber, the truth said in public, the peace made), and the world then runs at its own pace to the last night of its three days. The shows play on a clock that only the script moves, so the picture is of a second of the night that `--night-at` names. The default is three and a half seconds before the end: the camera has drawn back to the whole town, the line of the parade stretches from the street through the town to the hall, the main lantern is lit, the lanterns drift down the river, and the closing line of the night says in words how the game ended. The window is 1280 by 640, the shape of the town, and the picture is 1760 pixels wide, twice the width the READMEs show it at, which keeps its 256 colours under 400 KiB.

The pictures do not depend on how fast the machine is. The page is opened with `?until=1`, which holds the world after its first tick, and the script then moves it one tick at a time with the page's own pause and resume messages: a resume is answered with one tick, and the pause right behind it holds the world before the next tick is due. An action that the script sends is applied at the tick it was sent at. The core is a function of its seed and of the inputs it gets at each tick, so the same build gives the same game. Before each picture the script waits until nothing on the map moves, fixes the clock of the map's own animations and ends the page's CSS animations. While the world is held between two pictures, the word beside the pause button would say "paused". That hold is the script's and not the game's, so the script has the page say "running". A talk is the exception. While the manager talks, the core holds the clock by itself and no tick comes, whatever the script asks of the host, so the script does not step there: it acts, with a tag, a list of choices or a button of the card, or it leaves. An act takes some minutes of game time, and the script steps through them before the talk holds the clock again. A step that is made while a talk holds the world is an error that says so. In a talk the page is left as the game has it: before each picture the script lifts its own pause, and the word beside the pause button says that time is held.

The pictures show the core that is in `web/dist-e2e`. After a change to the core or the page, build the test build again and run the script again.

- `--only gif,notebook,ending,festival`, `--lang en,zh` and `--theme light,dark` choose what to make (default: everything). `--seed N` sets the seed of the game of the ending (default 4927, a game whose tree holds both sentences of its title). The first day and the festival night have a seed of their own. `--night-at S` takes a second of the festival night, or a list of them (then each picture gets its second in its name).
- `--fps` and `--width` set the frame rate (10) and the width (880, the width the READMEs show it at) of the GIF. A GIF has to stay under `--max-mb` (4), and the script lowers the number of colours until it does. A PNG has to stay under 400 KiB.
- `--jobs N` makes that many pictures at the same time (default 2), each in a browser of its own.
- `--out DIR` and `--dist DIR` set where the pictures go (default `docs/assets`) and which test build is served (default `web/dist-e2e`). `--chrome FILE`, `--tmp DIR` and `--keep` set the browser, the directory for temporary files, and whether to keep them.
- `--help` lists every option.

Web client网页客户端

One page for both hosts: a PixiJS map and a Preact interface, in Chinese and English, light and dark. It draws the frames it is sent and sends the player's actions back. 两种宿主共用同一个页面：PixiJS 地图和 Preact 界面，中英文，明暗主题。它画收到的帧，把玩家的动作发回去。

Browser host浏览器宿主

A module Web Worker runs the core in Pyodide and keeps saves in IndexedDB. Model calls go from the worker to the provider the player picks. Web Worker 里用 Pyodide 运行核心，存档放在 IndexedDB。模型调用由 Worker 发往玩家选定的提供方。

Server host服务端宿主

lantern-eve play runs the core under CPython and asyncio, one session per game, with frames over a WebSocket. Model calls go to the providers of a provider file, or to a mock. lantern-eve play 在 CPython 和 asyncio 下运行核心，一局一个会话，帧经 WebSocket 推送。模型调用走提供方配置文件里的服务，或走模拟模型。

lantern_core, one Python core：同一份 Python 核心

A pure state machine on the standard library alone. One call per tick: the inputs of that tick go in as JSON, and the frame, the events and the model requests come out as JSON. Nothing in it reads a clock, a file or the network, and its state hash is the same under CPython and under Pyodide. 只用标准库的纯状态机。每拍调用一次：该拍的输入以 JSON 传入，帧、事件和模型请求以 JSON 传出。核心里没有读时钟、读文件或联网的代码，状态哈希在 CPython 和 Pyodide 下一致。

Recording录像

The seed and the config, every input the core applied with its tick, and the state hash every 100 ticks. Both hosts write the same format, and lantern_core.replay rebuilds either one under CPython as it stands. 种子和配置，核心实际执行的每条输入及其所在的拍，以及每 100 拍一次的状态哈希。两种宿主写的是同一种格式，lantern_core.replay 在 CPython 下原样重建其中任何一份。

Web client网页客户端

One page for both hosts: a PixiJS map and a Preact interface, in Chinese and English, light and dark. It draws the frames it is sent and sends the player's actions back. 两种宿主共用一个页面。地图用 PixiJS 画，界面用 Preact 写，语言有中英两种，主题有深浅两套。页面画出收到的帧，把玩家的动作发回去。

Browser host浏览器宿主

A module Web Worker runs the core in Pyodide and keeps saves in IndexedDB. Model calls go from the worker to the provider the player picks. 核心跑在一个模块 Web Worker 里，用的是 Pyodide。存档放在 IndexedDB 里。模型调用从 worker 发往玩家选的提供方。

Server host服务端宿主

lantern-eve play runs the core under CPython and asyncio, one session per game, with frames over a WebSocket. Model calls go to the providers of a provider file, or to a mock. lantern-eve play 用 CPython 和 asyncio 跑核心，每局开一个会话，帧经 WebSocket 发给页面。模型调用发往提供方文件里的服务，或者交给 mock。

lantern_core, one Python core：同一份 Python 核心

A pure state machine on the standard library alone. One call per tick: the inputs of that tick go in as JSON, and the frame, the events and the model requests come out as JSON. Nothing in it reads a clock, a file or the network, and its state hash is the same under CPython and under Pyodide. 核心是一台只用标准库的纯状态机。宿主每拍调用它一次，把这一拍的输入以 JSON 交进去，再以 JSON 拿回帧、事件和模型请求。核心不读时钟，不读文件，也不联网。它的状态哈希在 CPython 和 Pyodide 下完全一样。

Recording录像

The seed and the config, every input the core applied with its tick, and the state hash every 100 ticks. Both hosts write the same format, and lantern_core.replay rebuilds either one under CPython as it stands. 每份录像存着种子和配置，还有核心用过的每条输入，每条都记着是第几拍用的。另外每 100 拍记一次状态哈希。两种宿主写同一种格式，哪一份都能由 lantern_core.replay 在 CPython 下原样重建。
